## 三、函数表

| 函数 | 语义 | 线程约束 |
| --- | --- | --- |
| `bole_init` | 启动运行时，立即返回 | 任意线程 |
| `bole_release` | 释放句柄，后台回收进程 | 任意线程，回调中禁止调用 |
| `bole_session_create` | 创建或复用会话 | 任意线程 |
| `bole_session_resume` | 恢复已持久化会话 | 任意线程 |
| `bole_submit` | 入队一条用户消息 | 任意线程 |
| `bole_cancel` | 取消当前活动 | 任意线程 |
| `bole_rsi_set` | 切换 RSI | 任意线程 |
| `bole_trace_export` | 导出轨迹 | 任意线程（可能耗时，后台执行） |
| `bole_set_event_callback` | 注册事件回调，替换旧回调 | 任意线程；`init` 之后、首次 `submit` 之前 |
| `bole_last_error` | 取最近错误文案 | 同句柄任意线程 |

待补：每个函数的完整签名、返回值、参数校验规则、空指针与重复调用的行为。

回调签名暂定 `void (*)(void* user_data, const bole_event* event)`，`user_data` 原样回传；事件里的字符串与结构体内存归 SDK 所有，**只在本次回调期间有效**，调用方要保留必须自行拷贝。重复注册替换旧回调，已入队的旧事件按新回调投递。

## 五、线程模型

数据面形态已定：**事件回调**，不用队列拉取。

1. 回调只在 SDK 自有的单条事件线程上触发，同一句柄串行、FIFO；不同句柄各有线程，互不阻塞。
2. 回调中允许调用 `submit`、`cancel`、`rsi_set`；禁止调用 `release`。调用方若要更新 UI，自行切回 UI 线程。
3. 回调必须快速返回（毫秒级）。SDK 内部是「独立读管道线程 + 有界队列 + 事件线程」，回调变慢只会让队列积压，不会阻塞运行时或控制面。
4. 积压时只丢最旧的 `TEXT_DELTA`，结构事件永不丢弃；结构事件队列溢出按故障处理（报 2xxx 并断开），不静默丢。
5. `bole_release` 立即返回；返回后不再投递新回调，已在飞行中的那一次允许完成，调用方必须容忍。
6. 回调不得让异常/长跳转穿过 C 边界；跨语言绑定自行捕获。

待补：控制面函数的阻塞上限、多句柄并发时的线程数上限、进程退出时回调的收尾顺序。
