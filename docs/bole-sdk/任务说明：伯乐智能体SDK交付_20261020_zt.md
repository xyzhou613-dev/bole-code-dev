## 一、背景

合作伙伴需在BJ一体机平台上验证 MCP 工具调用，需我方提供可集成的 SDK。

## 二、目标

IDE 调用 SDK 传入输入 → SDK 驱动伯乐大模型 + harness 框架 → 调度 MCP 工具完成任务 → 事件流实时回传 IDE。
SDK 是 harness 的薄封装：第三方只对接 SDK，不感知内部组件；harness 的内部语义不在 SDK 侧另造一套。

## 三、范围

**做**：Windows 版 SDK、示例程序、文档、离线部署包。

**不做**：硬件、一体机镜像与部署、IDE 改造、具体工具（MATLAB 等）的适配与授权。工具在本文中一律按"普通 MCP 工具"对待，不针对某个具体产品做定制。

## 四、交付物

| 交付物 | 要求 |
| --- | --- |
| SDK 库 | Windows x64 动态库，头文件 + 导入库 + 依赖清单 |
| 离线部署包 | 依赖全部随包提供，目标机无需外网、无需装 VS 运行库 |
| 示例程序 | 控制台示例 + 界面示例（界面示例用于验证长任务不卡） |
| 文档 | 接口说明（含线程模型）、集成指南、离线部署、错误码 |

## 五、接口要求

1. **导出 C ABI**：不导出 C++ 类与模板，避免跨编译器 ABI 问题；调用约定统一
2. **控制面非阻塞**：Init / Release / CreateSession / Submit / Cancel 立即返回，不等待模型或工具执行
3. **数据面异步**：事件回调或事件队列拉取，两者选一并写进文档；回调由 SDK 自有线程触发，调用方自行切回 UI 线程
4. **会话 - 任务 - 步骤三层**：可按 task 取执行轨迹，支持问题复现
5. **事件按 harness 阶段建模**：任务开始 / 计划 / 模型切换 / 工具调用开始与返回 / 验证 / 结束或错误。只有 thinking、tool_call、result 三类不够
6. **RSI 开关**：可通过配置文件与 SDK 接口两种方式开启或关闭，默认关闭；开关状态必须出现在事件流中，便于区分与排障
7. **取消语义明确**：立即中断还是步末终止；模型调用中、工具执行中分别如何响应
8. **工具注入方向明确**：内置工具与调用方注册工具是否都支持
9. **工具隔离**：工具以子进程方式调用，工具崩溃或超时不得拖垮宿主进程
10. **事件背压**：token 级增量可合并或限频

## 六、运行与部署要求

- 目标：Windows x64，内网环境，无外网出口
- 模型与 harness 服务位于内网，SDK 通过配置的服务地址访问
- 不得在运行时下载模型、依赖或工具；安装与升级均离线完成
- 接口字符串统一 UTF-8，路径差异由 SDK 内部处理

## 七、示例程序要求

- 提供一个**最简单的工具调用**作为示例（不依赖具体第三方工具），端到端耗时控制在 1 分钟内
- 界面示例需展示：输入、提交、实时状态区、结果区、取消按钮
- 示例即集成参考，源码随包提供

## 八、验收标准

1. 在无外网、无开发环境的 Windows 目标机上，示例程序跑通：输入 → 模型 → 一次工具调用 → 结果返回，全流程实时可见且在 1 分钟内完成
2. 任务执行期间界面可正常交互，取消生效
3. RSI 开关生效，且状态可在事件流中观测
4. 按文档独立集成可复现示例
5. 事件序列与 harness 实际执行阶段一致，不存在 SDK 侧伪造的状态
